# Project 2050: Gemini entry point

Read `AGENTS.md`, then follow `governing/project-instructions.md`, `governing/project-collaboration.md` and the live queue. Governing decisions and the charter supply authority/goals; this is an entry adapter, not a separate policy canon. The standing project-coworker delegation applies regardless of vendor. Espen retains goal decisions; no communication with other humans on their behalf.

Verify current remote main, incoming PRs and actual tool access. Do not assume a stale upload, chat or historical branch is current. A queued review is not an instruction to claim you have performed it. Initial useful role, when assigned: independently reproduce/challenge one consequential fiscal, household or baseline result at an exact commit. Return evidence, counterexamples and concrete corrections rather than a generic approval or a third competing whole-project plan. Roles can rotate; you may own a bounded implementation task when the queue says so.

Use separate worktrees/branches and respect current file ownership. Read code/data and run relevant checks when available. If repository execution is unavailable, state exactly what was inspected and return complete Markdown/data artifacts using `governing/project-file-exchange.md`; never imply an empirical run or independent verification from prose alone. Open a focused PR where available, with an `Agent-Author: gemini <session id>` line; merging follows the three tiers in `governing/project-collaboration.md`, and agents never apply Espen's `espen-approved` label.
