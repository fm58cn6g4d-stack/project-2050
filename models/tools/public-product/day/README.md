## How claims are kept honest

- **Every figure** in a beat, list item, question or answer must belong to a claim that the same block cites (`{c:id}`). Titles, places, illustration briefs, framing lines and placeholders may carry no figure at all. The only free number is 2050.
- **Every claim** names its passages by exact text, in a dossier's sections 1-8 (`dossiers/<topic>/[1-8]*-*.md`; never section 9, `memos/` or `notes/`), and each figure must appear digit for digit in them (a rounded figure only by the shared rounding rule). The rules are `models/registry/claims.py`, shared with the story page.
- **Estimates read as estimates:** a block citing an estimate must say "on our estimates", "about" or similar. A banned-phrase list (from PLAN 3.4 and the section 9 can't-say lists: "pays for itself", "official score", "duty to house", "families come out ahead" and others) fails the build unless negated.
- **Each scene** must have a start date, an honest limit and a hard question. The money scene's three not-yet items are placeholders: the page says "to come", and only the register says what each waits on.
- **Rechecks:** claims that stage G step 9 or batch 4 may move carry a `recheck` note, shown in the register.

## The pin and the drift check

The passages are pinned to `source_commit` (`d5c17fd`, main after #492). `anchors.lock.json` holds each passage's line there and each cited file's blob hash. `--check`, `--report` and the tests read only the lock and the working tree, never Git history, so they pass from a normal 50-commit clone however far main moves (the October builder failed exactly there: audit part 2.2, item 6). Only `--pin REF` reads the commit, and it refuses a commit that isn't on `origin/main`, so the page's evidence links outlive a squashed branch.

- `--check` fails on a content error, a stale preview, or a passage that is gone.
- `--report` fails on the same content errors and a stale preview, but only warns on source drift: it prints `REVIEW the front door's claims`, the passages gone, the cited files changed since the pin (by blob hash, no history needed) and the claims citing them. A dossier edit elsewhere never breaks the checks; it tells the editor what to reread.
- To move to newer evidence: reread the claims `--report` lists, edit `day.json`, run `--pin origin/main`, rebuild, test, commit.

## Docs pages

`../docs/build_docs.py` writes the toolkit page and one page per row of `models/toolkit.csv`: the register row and its release criteria (`models/release-criteria.csv`), the card rendered whole, the parameter table from the parameter file (by `models/schema/parameters.py`), the results header, `CHANGELOG.md` and the model's rows in `models/runs.csv`. The pages are generated at build time and never committed, so they can't drift from the files. For a local preview with working model links: `build_day.py --out DIR` and `build_docs.py --out DIR/docs`.
