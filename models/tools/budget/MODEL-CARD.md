# Federal budget model: model card

Role: the model card of `MOD-budget`, the core model that projects the whole federal budget year by year, FY2026-2056, on CBO's current-law baseline, and the change any reform makes to deficits, debt and interest (`charter/PLAN.md` 3.4). Status: **working** for current law, a reform given as yearly changes to revenue or outlays, and the plan as booked (brought to the toolkit standard in stage H step H4, 2026-11-25). It is not marked "preview" or "released": memo H1 is undecided. Owner: the Project 2050 lead session (Claude Code), which holds the budget model by `DEC-2026-11-08-02`, through GitHub issues on this repository. Version: 0.3.0, see `CHANGELOG.md`. License: none yet (memo H2; step H2b adds the line). Every output of this model is analysis of the evidence, not an official score or a benefit determination; its results files carry that line in their header.

License: the code is Apache 2.0, this card and the model's other writing are CC BY 4.0, and its parameter and data files are CC0 (see [`LICENSES.md`](../../../LICENSES.md); `DEC-2026-11-25-33`).

The benchmarks block under "Validation" is generated by `test_benchmarks.py` on every run, the evidence table by `models/schema/parameters.py` from `parameters.csv`; the rest is written by hand and changes only when the model does. Full benchmark results, with each one's source and reasoning, are in `benchmarks.md` (and `benchmarks.json` for other tools).

## What it answers

The model projects revenue, spending, deficits, debt held by the public and net interest for every fiscal year FY2026-2056, in nominal dollars and as shares of GDP, starting from CBO's February 2026 current-law projections. **Current law is the default run.** A reform is a file in `reforms/` (`run.py`'s docstring has the format); three ship with it:

| Reform file | What it is |
| --- | --- |
| `reforms/current-law.json` | No change: CBO's baseline with the documented FY2026 actuals and post-February adjustments (the same as leaving `--reform` out) |
| `reforms/cbo-2024-mandatory-2.json` | A neutral published option: CBO's *Options for Reducing the Deficit: 2025 to 2034*, Mandatory Spending Option 2 (extending the guarantee fee on Fannie Mae's and Freddie Mac's mortgages two years; SRC-1855, EV-HOU-556), as CBO's yearly figures, with the interest the smaller debt saves |
| `reforms/plan.json` | Project 2050's plan as booked: the agenda ledger with stage G's financing settlement (the recovery budget's case `mixed`) |

It answers, for any reform given as yearly changes:
- **the fiscal path**: deficits, debt and interest each year to FY2056, against current law on the same baseline;
- **the interest a reform adds or saves**, at CBO's projected rates on new borrowing (and one point higher, the stress case);
- for the plan, also **the D4 tests** Espen decided (the permanent programs paid for from FY2040, total debt and interest below the baseline, the room for time-limited investment), **the dedicated funds** (Social Security and Medicare HI on 75 years, paid leave, the carbon channel), and **how Congress would enact each row** (vehicle, discretionary or mandatory, budget authority).

The pieces, which share one baseline:

| Piece | File | What it does |
| --- | --- | --- |
| Fiscal model | `engine/fiscal-model.py` | The plan's rows as yearly changes to the baseline; interest; debt; the ten scenarios; the D4 tests |
| Data layer | `models/data/budget/`, `models/tools/budget/data.py` | CBO's and OMB's series, price indexes, and the one way to convert to real dollars or share of GDP |
| Provision library | `models/data/budget/provisions.csv`, `models/tools/budget/provisions.py` | How each row's money is enacted: kind, vehicle, budget authority, timing |
| Dedicated-funds engine | `engine/funds-model.py` | Social Security, Medicare Hospital Insurance and the plan's other self-funded programs, on 75 years |
| Counting rules and assumptions | `models/tools/budget/CONVENTIONS.md`, `models/data/budget/assumptions.csv` | Every rule and assumption, with an `ASM-` ID |
| Entry point | `run.py`, `reforms/` | One command: the baseline, ledger, paths and funds into a folder, then a reform against current law |

What the plan's runs are for:

- **Checking that the plan pays for itself the way Espen decided** (D4-B): the permanent programs paid for by FY2040, total debt and interest below the baseline, and the room left for time-limited investment.
- **Seeing how a change moves the fiscal path**: add, drop or resize a row and read the effect on deficits, debt and interest in nominal dollars, real dollars or share of GDP.
- **Showing spending the way Congress enacts it**: discretionary or mandatory, which bill carries it, and (roughly) the budget authority behind the outlays.
- **Comparing the plan with the current-law path** on the same baseline CBO uses.

## What it cannot answer

- **Not a cost estimator.** The model doesn't work out what a bill costs. Each row's ten-year cost comes from the ledger (`models/data/inputs/`), where it is sourced; the model spreads that total over the years and carries it forward. A benchmark that "reproduces" a score tests the spreading and the interest, not the cost (PS-1, PS-2).
- **Not a forecast.** Like CBO's baseline, it shows what current law plus the plan would do, not what Congress will do.
- **Not dynamic.** The economy doesn't respond to the plan, and interest rates don't respond to borrowing. The model can run a growth stress on CBO's rules of thumb (SE-2a, SE-2b), but the plan doesn't change growth in any scenario. Dynamic effects are a separate, labeled scenario (DEC-DYN).
- **Not a substitute for an official score.** CBO and JCT will score the plan's bills against their own baseline of the day. The model is built to land near them, and the benchmarks show how near.
- **Not yet a source for budget authority figures.** Budget authority for discretionary rows is rough (`ASM-SPENDOUT`, and for new nondefense programs the placeholder `ASM-SPENDOUT-NEW`; PS-4a is bounded and PS-4b fails, reported as not fully validated).
- **Not a cost estimator for a reform file either.** A `rows` reform's yearly figures are taken as given (for the CBO option, as CBO published them against its January 2025 baseline); the model adds only the interest. It never produces an official score or an individual benefit determination.

## Mechanisms and their research basis

- **The baseline** is CBO's, taken as published (ASM-BASE-CBO, SRC-1166, SRC-3395): the ten-year projection to FY2036, then CBO's long-term shares of GDP times its GDP (ASM-BASE-LT-SHARES). FY2026 is replaced by the actuals and two tariff adjustments are made, each in the table above. Nothing in the baseline responds to a reform.
- **A reform's yearly change** is added to revenue or outlays as given. For the plan, each ledger row's ten-year total is spread over the years with its profile (start year, ramp, growth index, permanence; `models/data/inputs/fiscal-profiles.csv`; ASM-PROF-DEFAULT, ASM-PROF-RAMP and the other profile rows) so the FY2030-39 sum equals the ledger's midpoint (ASM-CALIB-MID); PS-1 and PS-2 check that spreading against JCT's and CBO's year-by-year scores.
- **Interest on added debt** is charged at the higher of CBO's average rate on debt and a 40/60 blend of its bill and 10-year note rates through FY2036, then CBO's long-term implied rate, with half a year of interest on each year's own borrowing (ASM-RATE-MARGINAL, ASM-RATE-HALFYEAR; ID-4a checks it). The stress case adds a point, phased in as Treasury's debt rolls over (ASM-RATE-ROLLOVER, SE-1 against CBO's rules of thumb, SRC-1161).
- **Growth** changes only in the growth stress, on CBO's 2026 rules of thumb scaled to the size of the change (ASM-GROWTH-LINK; SE-2a and SE-2b, in-sample). No reform changes growth: the scoring is conventional (ASM-DYN-CONVENTIONAL); the plan's dynamic reading is a separate scenario (DEC-DYN).
- **The dedicated funds** run the Trustees' 2026 intermediate projections year by year on 75 years (SRC-3810; TF-1 to TF-3) and add the plan's provisions from SSA's scores.
- **The method's counting rules** are in `CONVENTIONS.md`; the benchmarks below are what tests them.

## Limits

**What the model doesn't count yet.**
- **FY2029 is only partly priced.** Every total and test runs FY2030-39, but the plan starts in January 2029. Since B6, FY2029 is a separate, disclosed line read on the debt path as scenario DEC+FY29 (`ASM-FY2029-LINE`, `models/data/inputs/fiscal-fy2029.csv`): CAP-7S's $5 billion is priced, moved from FY2030 as Espen decided on October 26; FAM-1's and MOV-29's FY2029 effects are listed as unpriced, not zero. Each bill is also scored in its own CBO window, R1 over FY2029-38 (`ASM-BILL-WINDOW`; `provisions.md`).
- **The cautious reading is disclosed, not tested.** The tests use each row's midpoint (`ASM-CALIB-MID`). Since B6 the ledger's high-cost and low-revenue ends reach the model as scenario DEC-CAUT, reported beside the D4 tests with the one-point stress case (DEC-R1), neither with a pass-or-fail condition (choices 2 and 4; `ASM-CALIB-CAUTIOUS`). Taking every high end at once is a bound, not a likely outcome: it adds $12.24 trillion to the FY2030-39 general-fund deficit.
- **Interest rates don't respond to the plan's borrowing** (`ASM-RATE-NOFEEDBACK`).
- **Social Security's reserve investment (SS-8.01) is recorded at zero.** The recovery budget's central case carries the decided package with SS-7.01's one-point fallback on its expected path, 2037-46 (`ASM-SS-FALLBACK`, `DEC-2026-11-12-13`). How the budget should record the trust funds' stock purchases is not settled, so SS-8's yield (about +0.05 to +0.2% of payroll on the trust funds) and its purchases are left out. The caregiver credit (SS-B4.01) is not on the fund engine yet either.
- **Rows CBO's baseline already contains read $0.** Defense is the visible case: NSC-1A reads $0 against CBO's baseline (`CONVENTIONS.md`, section 1; the defense memo).

**Carried from earlier pieces.**
- OMB's and CBO's historical outlays differ by up to 0.6% a year in FY2020-25 (B2's README, "Which administration"). B4 doesn't explain the gap; neither series is used for those years in any benchmark here.
- The largest dynamic-feedback row, DY1, rests on a JCT figure recorded "from memory" (`CONVENTIONS.md`, section 8). It enters only scenario DEC-DYN.
- **The engine still builds the plan's ledger in every run.** `run.py` builds the ledger and the engine's scenarios (the plan's) before applying any reform, because the engine's baseline scenario is computed beside them; a current-law or CBO-option result does not depend on the ledger, but the run reads its tables. Separating them is a known issue below.

**What the groups test.**
- **Baseline (BL):** that the model's starting point is CBO's, exactly. B2's test does this; B4 reports it.
- **Accounting identities (ID):** that the arithmetic holds in every year and scenario: deficits, debt, interest and unit conversions. These must always pass, and the test run fails if one doesn't.
- **Published scores (PS):** that the model's methods land near CBO's and JCT's own numbers for the same inputs: the timing of a tax provision, the interest on added deficits, and the conversion of appropriations into spending.
- **Sensitivity (SE):** that the model responds to higher rates and slower growth as CBO's rules of thumb say (CBO's April 2026 report on the February 2026 baseline).
- **Trust funds (TF):** that the dedicated-funds engine reproduces the 2026 Trustees and SSA's actuaries.

A miss is a result. Nothing in the model or the tolerances is changed to make a benchmark pass; a fix to a method is its own change, reviewed on its own.

### What is not fully validated

The workflow says nothing new feeds a public or decision figure until B4's benchmarks pass. Codex's milestone review asked for changes on that ground (PR #115).

**B4 milestone: met, by Espen's decision (DEC-2026-11-12-11, board question 0r, November 12, 2026), with PS-4b reported as not fully validated.** With B6's fixes (TF-2 now passes; PS-4a is bounded and PS-4c added, #272), every benchmark passes or is bounded except PS-4b. PS-4b still fails, and its miss stays on the results page. Espen closed the milestone with it reported as not fully validated, because spending rates vary with the agency, the program, whether delivery infrastructure exists or must be built, whether new rules must be written and what state and local partners do, and modeling all of that is not worth it in the baseline budget model. Everything else the model reports is supported: the baseline, the accounting identities, ten-year totals, interest and its stress case, the growth stress (in-sample), both trust funds, and the arithmetic of the D4 readings.

**Why PS-4b is not fully validated.** Its only CBO benchmark, the 2024 Israel security supplemental's State title, is 95% Foreign Military Financing, which CBO records as spent almost at once (-72 points against the library by year 1): an account rule no average can reproduce. No CBO estimate of a regular nondefense act is benchmarked (three checked so far give one year only: the two FY2026 House estimates and H.R. 1968's full-year 2025 continuing resolution), so nothing shows the nondefense average holds for a single act's mix; PS-3b tests only the average against CBO's projected totals.

**The placeholder for new programs (`ASM-SPENDOUT-NEW`).** As Espen asked, a light research pass on historical averages set an evidence-backed placeholder for new nondefense programs that need new rules or delivery infrastructure: 10% of budget authority spent in the first year, 36% by year 2 and 58% by year 3, all of it by year 5, against the established average's 25%, 60% and 90%. It averages CBO's estimates for ARRA's appropriations (2009) and IIJA's division J (2021), with IIJA as the slow end and the average as the fast end of its range (`models/data/budget/README.md`, "Spend-out of new programs"). Six bills use it (EDU-8, DEM-1, DEM-11, DEM-16, DEM-17, SAF-10) and the declined option C34. It moves only the timing of their budget authority, not their outlays or any deficit, and it is a placeholder, not a benchmark: nothing tests it, and it does not change PS-4b, which tests the average against a fast-spending act.

These readings stay **diagnostic only** and must not be used in a decision memo, a dossier's cost section or a public page:

| Reading | Benchmark | Status, and what would validate it |
| --- | --- | --- |
| The year-by-year timing of a single nondefense row's outlays and budget authority | PS-4b (fail; not fully validated, DEC-2026-11-12-11) | Kept out of decision and public figures. A CBO estimate of a regular year's nondefense appropriations, by year, checked as PS-4c checks defense, would validate the average; account-level rates, where a row's timing matters to a decision, would narrow it further. New programs' budget authority uses the placeholder above, with its range |
| The size of any growth stress reading | SE-2a, SE-2b (pass, in-sample: bookkeeping only) | The link is CBO's 2026 table itself, so the pass tests only the bookkeeping and the debt service. Two passing benchmarks are weaker than their status suggests, and Codex's review says so too:
- **PS-1 and PS-2 check methods, not costs.** The cost total goes in from JCT; the benchmarks check how the library spreads it over the years and what interest the model adds. They do not show that the model can estimate a cost.
- **PS-2 is a near match.** It is about 13% from CBO against a 15% tolerance, now on Table 2's actual years; the remaining difference is mostly the two interest-rate vintages.
- **PS-3b is partly in-sample.** B2 set the nondefense spend-out shares' overall level to match CBO's outlays over the same years the benchmark checks, so the total is fitted. Only the year-by-year timing, taken from OMB's history, is tested. PS-3a (defense) is out of sample since B6's spend-out fix: the defense shares are CBO's own rates from three defense acts, not fitted to the baseline.

### What is bounded

A *bounded* benchmark misses its tolerance, but its miss stays under a fixed ceiling written in `test_benchmarks.py` (PS-4a's was set in review, after its miss was known), a companion benchmark the model can fail shows the method holds where it should, and the readings that depend on it carry the miss as a stated range (`WORKFLOW.md`, "Benchmarks before trust"). It is resolved, not passed: the reading may be used with its range, never as more precise than that.

| Reading | Benchmark | Range it carries | Why the miss is not the method's |
| --- | --- | --- | --- |
| The year-by-year timing of a single defense row's outlays and budget authority | PS-4a (bounded; ceiling 20 points) | Up to 18 points of the row's budget authority in any of its first four years; more for a row that is mostly procurement or research | The 2024 Israel supplemental's defense title is weighted to procurement and research, which spend slowly. CBO's own regular-act rates miss it by about as much, and they hold for a regular year's mix: each of three NDAA estimates is within 5.1 points of the other two (PS-4c, pass) |

Ten-year totals do not depend on it: every share is positive and each group's money is spent once, at the level CBO's baseline gives (PS-3a, PS-3b). Rates by account or by program type, where a row's mix is known, would narrow the ranges; that is for when a row's timing matters to a decision.

What the benchmarks do support now: the baseline (BL-1), the accounting identities (ID-1 to ID-5), the year-by-year timing of the discretionary spend-out in total (PS-3a out of sample, PS-3b) and of a regular year's defense appropriations (PS-4c), the trust-fund engine for Social Security and Medicare HI (TF-1, TF-2, TF-3), the size and timing of the interest-rate stress case (SE-1, since B6 phased it in), and the arithmetic behind the D4 readings. The D4 readings also rest on the ledger's midpoints, which no benchmark tests (`CONVENTIONS.md`, choice 2). B4 changes none of those figures.

## Known issues

**Found by the benchmarks.**
- **Nondefense appropriations used to turn into too little spending (PS-3b, now fixed).** In the first run, the library's spend-out fell about 11% short of CBO's nondefense outlays. The library had rescaled B2's spend-out shares down to one, dropping the highway, transit and airport spending that counts as discretionary outlays though its budget authority is mandatory. B3's fix (PR #118) uses B2's CBO-calibrated shares and carries that spending on its own; PS-3a and PS-3b now pass. Budget-authority figures stay rough (`ASM-SPENDOUT`): the shares' timing is history's, not CBO's account-by-account rates.
- **The default timing for a tax provision can grow too fast (PS-1).** Revenue rows grow with their tax base by default (`ASM-PROF-REVENUE`). JCT's estimate for the four household deductions grows much more slowly; the yearly figures pass, but the growth rates differ by about two points a year.
- **The interest stress case used to reprice all debt at once (SE-1, now fixed).** A one-point rise applied to the whole debt from its first year, where CBO's rules of thumb phase it in as debt is refinanced: on CBO's scenario the model added $502 billion of interest over FY2027-36 against CBO's $383 billion, and $32 billion against $14 billion in FY2027. B6 (item 1) phases the rate in on Treasury's maturity structure (`ASM-RATE-ROLLOVER`); SE-1 now passes, within 1% of CBO's ten-year total. The stress cases DEC-R1 and BASE-R1 are lower as a result: the baseline's 2056 debt under the stress is 217% of GDP, not 224%.
- **The model had no response to slower growth (SE-2, now built).** CBO's baseline was taken in dollars, so slower growth changed nothing, where CBO's rules of thumb add $166-317 billion to deficits over ten years for a 0.1-point slowdown. B6 (item 2) adds a growth link from CBO's 2026 rules of thumb (`ASM-GROWTH-LINK`). It is simple: CBO's effects as shares of GDP by year, scaled to the size of the change, continued on a straight line after 2036; the plan's own rows don't shrink with GDP. SE-2a and SE-2b pass, in-sample.
- **The defense spend-out had a negative share (PS-4a, now fixed; bounded).** B2's four-year fit to OMB's totals gave defense a -4.3% fourth share, so a single act "spent" 103% of its money by year 3. B6 replaced it with CBO's own rates, the average of its spend-out of three regular defense acts (`ASM-SPENDOUT`): every share is positive, CBO's projected defense outlays come back within 1.7% a year without fitting (PS-3a), and each act is within 5.1 points of the others (PS-4c).
- **One average spend-out for every established discretionary row (PS-4a bounded, PS-4b fail, not fully validated).** Run on a single act, CBO's estimate of the 2024 Israel security supplemental, the library's shares still misplace the timing: too fast for the procurement-heavy defense title (18 points ahead by year 2) and far too slow for the State title, which is 95% Foreign Military Financing that CBO spends almost entirely in its first year. The ten-year totals are right; defense rows' year-by-year outlays and budget authority carry the range in "What is bounded", and nondefense rows' are not fully validated (DEC-2026-11-12-11). New nondefense programs that need new rules or delivery infrastructure now use a slower placeholder (`ASM-SPENDOUT-NEW`), which changes their budget authority's timing only.
- **Medicare Hospital Insurance was a year off the Trustees (TF-2, now fixed).** The engine had the Trustees' HI rates at six years only, interpolated in straight lines, which understated HI's cost in 2027-39 by up to 0.12 point of payroll: depletion read 2034 against the Trustees' 2033 and the balance -0.64% against -0.56%. B6 gave it every year the Trustees publish (Table III.B7); it now lands on 2033, 89% payable and -0.56%. CBO's own February 2026 projection puts HI's exhaustion much later, in FY2040: the two forecasters differ by far more than the engine did.

**Found by B3 (`provisions.md`, "Where the files disagree"; reported there, not fixed, since fixing them changes adopted inputs).** B6 (item 3) sorted them. The seven reconciliation rows, and DEM-11 and CAP-7S, are open design choices (board 0d), each now citing what the dossier documents already say; the library can score a provision split across vehicles, each part in its own category. None is a plain booking error: C33 is a net trim whose faithful booking is a split. The timing and growth findings (c) and (d), with DEM-11's indexation and the excise offset rate, went to Espen as board question 0q and are now booked (`DEC-2026-11-12-08`).
- **(a)** Seven rows on a reconciliation bill sit in a discretionary category: EDU-4, LAB-8, NSC-10, MOV-29, DEM-17, SAF-10, MOV-30. Reconciliation carries only mandatory spending and revenue.
- **(b)** Four rows' categories don't match the ledger's text: SAF-10, DEM-11, CAP-7S and C33.
- **(c)** MOV-29 and MOV-30 had no end year in the model, though the ledger names top-up years. Fixed by `DEC-2026-11-12-08`: they are booked in those years from the transportation model, and MOV-31's successor line carries the model's general-fund draw after 2039. `DEC-2026-11-12-10` starts that line in FY2037 at the model's figures ($49.1B, $41.6B and $33.8B in FY2037-39), so no year after the acts end is left empty.
- **(d)** C35: the ledger says the exemption is frozen in dollars, so its revenue grows faster than GDP; the model grew it with GDP. Fixed by `DEC-2026-11-12-08`: GDP plus 2.0 points a year, derived from CBO's and JCT's estate tax projections (`ASM-PROF-ESTATE`).

**Unknown fields.** Where the repository doesn't say how a row is enacted (its vehicle, appropriation type or budget authority), B3 marks it `unknown` rather than guess. The counts are in the results block above; the rows are listed in `provisions.md`. For most rows, the growth index and end year are the model's assumption, not something the law states.

**Found in step H4 (the release).**
- **The engine builds the plan's ledger in every run** (above, "Limits"). The released command reads as general, but the engine underneath still computes the plan's scenarios; a later version can give it a current-law-only path.
- **Only the plan's scalar parameters are on the parameter schema.** The bulk data (CBO's, OMB's, the Trustees') are files with their own checks; most method choices in `assumptions.csv` have no tested range, so `parameters.csv` shows them as "not varied".
- **The bookings and the fiscal-path analyses moved to `models/bookings/`, but four dossier tools did not yet**: `democratic_renewal_cost.py`, `democratic_renewal_pace.py` and `test_democratic_renewal.py` (PR #493 edits them; they move after it merges), and `family-financing.py`, `health/`, `strategic-review/`, `capacity-review/`, `financing-protection/` (`.github/scripts/run-checks.sh` or several scripts name their paths; they move with step H2b's checks wiring).
- **No fresh-clone job runs `run.py` in CI yet** (step H2b); it was checked by hand from a fresh clone (the PR for step H4).

## How to run

From a fresh clone, with Python 3 and nothing else (every input is committed):

```bash
python3 models/tools/budget/run.py --out DIR                                                    # current law
python3 models/tools/budget/run.py --reform models/tools/budget/reforms/cbo-2024-mandatory-2.json --out DIR
python3 models/tools/budget/run.py --reform models/tools/budget/reforms/plan.json --out DIR       # the plan as booked
python3 models/tools/budget/test_run.py                                                         # the command's tests
```

Each run writes into `DIR` the baseline (`fiscal-baseline.csv`), the ledger (`ledger.json`), the engine's paths (`fiscal-model.json`, `fiscal-paths.csv`), the dedicated funds (`funds.json`, `dedicated-funds.md`), and `paths.csv` (current law and the reform, FY2026-2056) and `results.json` (the toolkit's results header, then the reform, its rows and the headline years). The plan's run also writes `plan-paths.csv`, which equals `models/data/recovery-budget-paths.csv`, case `mixed`, cell for cell. `--from-build build` reuses run-all's engine run; `--record` records the run (below). To try another published option, copy `reforms/cbo-2024-mandatory-2.json` and type in CBO's yearly row.

The whole suite, with every benchmark and the drift check:

```
bash models/tools/run-all.sh            # rebuilds everything into build/ and runs every test, including the benchmarks (step 6e)
bash models/tools/run-all.sh --write    # the same, then copies the outputs into place, including this card's generated blocks
python3 models/tools/budget/test_benchmarks.py   # the benchmarks alone, after a run-all
```

`bash .github/scripts/run-checks.sh` runs the full PR checks: the rebuild, the drift check (it fails if `benchmarks.md`, `benchmarks.json`, this card or a reference result no longer match the code and data) and the other test suites.

**When a source arrives.** The documents listed at the end of `benchmarks.md` turn pending benchmarks into pass or fail. Save the upload into the library, record its figures in `test_benchmarks.py` beside the benchmark with the `SRC-` ID, set the tolerance with its reason, and rerun.
